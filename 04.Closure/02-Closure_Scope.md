# 클로저
JavaScript에서 클로저(Closure)가 어떻게 접근 권한을 제어하고,  
지역 변수를 보호하는지를 시각적으로 설명하고 있습니다.  
아래에 그 내용을 코드와 함께 문서 형식으로 정리.  

## 📘 클로저의 접근 권한 제어와 지역 변수 보호
### 1. 핵심 개념 요약
클로저는 다음과 같은 기능을 제공합니다:


| 기능             | 설명                                                                 |
|------------------|----------------------------------------------------------------------|
| 접근 권한 제어     | 외부에서 직접 접근할 수 없고, 클로저를 통해서만 내부 변수에 접근 가능                     |
| 지역 변수 보호     | 함수 내부에서 선언된 변수는 외부에서 접근 불가 → 데이터 은닉 가능                         |
| 데이터 보존 및 활용 | 함수가 종료된 이후에도 내부 변수 상태를 유지하며 활용 가능 → 상태 유지형 함수 구현 가능 |


### 2. 코드 분석
```javascript
function a() {
  var x = 1;
  function b() {
    console.log(x);
  }
  b();
}
a();
console.log(x); // ❌ 오류 발생: x는 지역 변수이므로 외부에서 접근 불가
```


#### 🔍 설명
- x는 함수 a 내부에서 선언된 지역 변수입니다.
- 내부 함수 b는 x를 참조할 수 있습니다 → 클로저가 생성됨
- b()는 x를 출력할 수 있지만, console.log(x)는 오류입니다 → x는 a의 지역 변수이므로 외부에서 접근할 수 없습니다.
#### ✅ 클로저의 역할
- 함수 b는 x를 기억하고 접근할 수 있는 클로저입니다.
- x는 외부에서 직접 접근할 수 없으므로 보호된 상태입니다.
- 이 구조는 정보 은닉과 접근 제어를 가능하게 합니다.

### 3. 클로저를 활용한 안전한 접근 예시
```javascript
function createAccessor() {
  let secret = 42;

  return {
    get() { return secret; },
    set(v) { secret = v; }
  };
}
```
```javascript
const accessor = createAccessor();
console.log(accessor.get()); // 42
accessor.set(100);
console.log(accessor.get()); // 100
```

#### 🔐 이 구조의 장점
- secret은 외부에서 직접 접근 불가
- get, set 메서드를 통해서만 접근 가능 → 접근 권한 제어
- secret은 createAccessor의 렉시컬 환경에 존재 → 지역 변수 보호
- accessor는 secret을 기억하고 있음 → 클로저

### 4. 시각적 구조 요약
```
createAccessor()
 └── secret (지역 변수)
      └── get() → secret 반환
      └── set(v) → secret 수정
 └── 반환된 객체는 secret을 기억하는 클로저
```


## ✅ 결론
클로저는 JavaScript에서 정보 은닉, 접근 제어, 상태 유지를 가능하게 하는 강력한 기능입니다.
그림 속 예제는 이를 직관적으로 보여주며, 클로저가 어떻게 지역 변수를 보호하고 외부 접근을 제한하는지를 잘 설명하고 있습니다.

# 클러저 본질

클로저(Closure)의 본질은 바로 지역 변수의 해제를 막고, 그 **컨텍스트 환경(Lexical Environment)** 을 살려두는 것입니다.

## 🔍 자바스크립트의 일반적인 변수 해제 흐름
보통 함수가 실행되고 종료되면, 그 안에서 선언된 지역 변수들은 스택에서 제거되고 메모리에서 해제됩니다.  
하지만 클로저가 생성되면, 그 함수 내부의 지역 변수들은 **GC(Garbage Collector)**가 제거하지 못합니다.  
왜냐하면 다른 함수가 그 변수들을 참조하고 있기 때문.  

## 📦 클로저가 지역 변수의 컨텍스트를 유지하는 방식
```javascript
function outer() {
  let secret = 123;

  return function inner() {
    return secret;
  };
}

const fn = outer(); // outer는 종료되었지만...
console.log(fn());  // 123 → inner는 secret을 기억하고 있음!
```
- outer()는 실행되고 종료되었지만,
- inner()는 secret을 참조하고 있으므로,
- secret이 포함된 outer의 렉시컬 환경 전체가 살아남습니다.
- 즉, 클로저는 함수의 생명 주기를 넘어 지역 변수의 생명 주기를 연장합니다.

## 🧠 메모리 관점에서 보면
- 클로저는 함수가 선언된 시점의 스코프 체인을 캡처합니다.
- 이 스코프 체인은 함수가 살아있는 한 메모리에서 해제되지 않습니다.
- 그래서 클로저는 상태를 유지하는 함수, 정보 은닉, 모듈화에 매우 유용하지만,
- 동시에 메모리 누수의 원인이 될 수도 있습니다 (특히 DOM 참조가 클로저에 남아 있을 경우).

## ✅ 결론
클로저는 단순히 "함수가 변수 기억함"이 아니라, 지역 변수의 컨텍스트 전체를 보존하는 구조입니다.  
이 덕분에 JavaScript에서 객체지향 없이도 상태 유지, 정보 은닉, API 설계가 가능해지는 거죠.

# Javascript / Rust

Rust의 클로저(closure)는 JavaScript의 클로저와는 메모리 관리 방식, 스코프 유지, 안전성 측면에서 꽤 다릅니다.  
아래에 두 언어의 클로저 차이를 정리해 드릴게요.

# 🧠 JavaScript vs Rust 클로저 비교

| 구분              | JavaScript 클로저                                      | Rust 클로저                                                |
|-------------------|--------------------------------------------------------|------------------------------------------------------------|
| 스코프 유지 방식   | 선언 당시의 **렉시컬 환경 전체**를 캡처하여 참조 유지       | 필요한 변수만 캡처 (자동 참조, `move`, `&`, `&mut`로 제어)   |
| 메모리 관리        | GC 기반 → 참조가 남아 있으면 해제되지 않음               | 소유권/라이프타임 기반 → 스코프 벗어나면 자동 해제           |
| 캡처 범위          | 사용 여부와 관계없이 환경 전체를 유지                    | 실제로 사용된 변수만 캡처                                   |
| 안전성             | 런타임에서 오류 가능성 있음 (undefined, 메모리 누수 등)   | 컴파일 타임에 borrow checker로 안전성 보장                   |
| 성능               | 유연하지만 메모리 누수 위험 존재                         | 제어 가능하고 안전하지만 유연성은 제한적                     |
| 캡처 방식 예시      | 자동 참조                                               | `move` (소유권 이동), `&` (불변 참조), `&mut` (가변 참조)    |


## 🔍 Rust 클로저의 특징
### 1. 캡처 방식이 명시적
```rust
let x = 10;
let f = || println!("{}", x); // x는 자동으로 참조됨
```
- ||는 클로저를 의미하며, x는 자동으로 참조(&x)됨
- 필요 시 move를 붙여 소유권을 넘길 수 있음
```rust
let x = String::from("hello");
let f = move || println!("{}", x); // x의 소유권을 클로저로 이동
```

### 2. 클로저가 스코프를 벗어나면 변수도 해제됨
```rust
fn make_closure() -> impl Fn() {
    let x = 42;
    move || println!("{}", x)
}
```

- x는 클로저 내부로 move되며, 클로저가 drop되면 x도 drop됨
- GC가 없고, 명시적 소유권으로 메모리 누수 없음

## ✅ 결론
JavaScript는 클로저가 환경 전체를 캡처하고 오래 유지되기 때문에 메모리 누수 위험이 있지만,  
Rust는 소유권과 라이프타임 시스템 덕분에 클로저가 안전하고 예측 가능하게 동작합니다.  
즉, Rust에서는 클로저가 지역 변수의 해제를 막는 게 아니라, 필요한 변수만 캡처하고, 스코프에 따라 자동 해제되는 구조입니다.
