# 리터럴을 사용
지금 보여주신 코드가 바로 배열을 만들 때 리터럴 문법([])을 쓰는 것이 안전하고 직관적인 이유를 잘 설명해줍니다. 

## 🔎 배열 리터럴 vs new Array()
### 1. 배열 리터럴 []
```javascript
var a = [3];
console.log(a.length); // 1
console.log(a[0]);     // 3
```

- [값] 형태로 바로 요소가 들어간 배열을 생성.
- 직관적이고 예측 가능한 결과.
- 숫자든 문자열이든 그대로 요소로 들어감.

### 2. new Array()
```javascript
var a = new Array(3);
console.log(a.length); // 3
console.log(a[0]);     // undefined
```

- 숫자 하나만 넣으면 "배열 길이"로 해석됨.
→ [3]이 아니라 길이가 3인 빈 배열이 만들어짐.
- 요소가 아니라 배열 크기를 지정하는 특별한 동작 때문에 혼동을 일으킬 수 있음.

### 3. 숫자가 정수가 아닐 때
```javascript
var a = new Array(3.14); // ❌ RangeError: invalid array length
```
- new Array()는 정수 길이만 허용.
- 실수나 음수는 에러 발생.

### 4. 배열 리터럴은 안전하다
```javascript
var a = [3.14];
console.log(a[0]); // 3.14
```

- 리터럴은 항상 "요소"로 해석되므로 예측 가능.
- 에러 없이 원하는 값이 배열에 들어감.

### 5. 중첩된 경우
```javascript
var a = new Array([3]);
console.log(a);    // [ [3] ]
console.log(a[0]); // [3]
```

- new Array([3])는 [3]이라는 배열을 요소로 갖는 배열을 생성.
- 직관적이지 않고 헷갈리기 쉬움.

## ✅ 결론
- 리터럴 문법 []을 쓰는 것이 권장되는 이유
- 직관적이고 예측 가능한 결과를 얻을 수 있음.
- new Array()는 숫자 하나일 때 "길이"로 해석되는 특수 규칙 때문에 혼동을 줌.
- 실수나 음수는 에러를 발생시켜 불안정함.
- 코드 가독성과 유지보수성 측면에서도 리터럴 방식이 더 명확함.

## 👉 요약:
- 배열은 항상 [] 리터럴로 만들자.
- new Array()는 특별한 경우(길이 지정) 외에는 쓰지 않는 것이 좋습니다.
